Changes and known limitations

Current release: Version 0.12.0 — 21 October 2026. This page gives a simple, user-facing release history without requiring access to GitHub.

0.12.0 — Zero capacity is now honored

  • Entering zero for Micro-enterprises / Unit now creates a genuine no-network stress case.
  • The old calculation silently changed zero back to the default of 20, making the adverse scenario look identical to the healthy Malawi reference run.
  • With zero capacity, the model now launches no enterprises, builds no toilets, and reports the resulting senior-debt shortfall instead of a viable verdict.
  • Missing or malformed inputs still stop before calculation; only an explicit, valid zero is preserved.
  • F-50 is resolved. The default Malawi result and all 21 recorded scenarios are unchanged.

0.11.0 — Monthly implementation table corrected

  • Every monthly figure now appears under the correct heading. A missing header previously shifted ME finance, operating-cost, investor-payment, net-cash, and ending-cash values one column to the right.
  • The table now labels New MEs (a count) separately from New ME Loans (a currency amount).
  • New-enterprise counts now use the exact number launched by the simulation instead of dividing the loan amount by setup cost alone.
  • At the current Malawi defaults, the old shortcut overstated launches by 3.8 times because it ignored working capital included in each enterprise loan.
  • F-49 is resolved. Cashflows, headline results, and the five-year Malawi reference result are unchanged.

0.10.0 — Advice is now model-tested

  • The advice button now recalculates the current scenario and shows only changes that were tested by rerunning the model.
  • The old advisor could recommend a longer investor term even where the model showed that it worsened repayment; that duplicate path has been removed.
  • The control is now labelled “Review model-tested advice” rather than implying that its deterministic calculations are artificial intelligence.
  • Recommendations appear beside the viability result and never alter the user’s assumptions.
  • F-48 is resolved. Model outputs and the five-year Malawi reference result are unchanged.

0.9.0 — Scenario exports made self-consistent

  • CSV and clipboard reports now retain the exact assumptions used by the successful calculation, even if the form is edited before export.
  • The copied balance sheet now uses the model's tracked senior liability, including capitalised interest, instead of reconstructing a smaller number.
  • The copied leverage ratio now uses the same definition as the dashboard and canonical KPI.
  • Two new export regressions verify the scenario snapshot, senior liability, and leverage.
  • F-47 is resolved. Model outputs and the five-year Malawi reference result are unchanged.

0.8.0 — Invalid inputs stop before calculation

  • Blank, malformed, infinite, and mathematically invalid inputs now produce no model result instead of allowing NaN, Infinity, a crash, or a plausible-looking answer.
  • The model reports every detected field together so users can correct the scenario in one pass.
  • A failed rerun clears the previous result, preventing an older scenario from being exported under newly entered assumptions.
  • Checks cover mathematical requirements only; the model does not invent maximum prices, rates, capital, or programme scale.
  • F-46 is resolved. The 21 recorded scenarios and five-year Malawi reference result are unchanged.

0.7.0 — Investor debt settlement completed

  • Old capitalised investor interest is now repaid before current interest and original principal.
  • Paying old interest reduces both the arrears balance and the senior liability; the model separately reports total capitalised, later repaid, and still outstanding.
  • At wind-up, positive loan-ledger cash is paid to the senior investor before the ledger freezes. Grant cash remains ring-fenced.
  • Two new integrity checks reconcile the senior balance and prevent a wound-up fund from retaining loan cash while senior debt remains unpaid.
  • F-44 and F-45 are resolved. The five-year Malawi reference result is unchanged.

0.6.0 — Evidence-based defaults and safer country data

  • Malawi now opens with dated population, sanitation-gap, growth, and income observations plus sourced household size, district count, enterprise capital, loan terms, and time-saving assumptions.
  • Country loading changes only observed target population, population growth, and income. CPI, commercial lending, poverty, Gini, and sanitation coverage are shown as dated context; they do not silently set financing, losses, costs, capacity, or subsidy policy.
  • Missing essential country observations clear the affected field and pause automatic calculation instead of retaining another country’s value.
  • A genuine 0% portfolio write-down now remains zero. Demand now grows before current production is subtracted.
  • DALY and carbon assumptions default to zero until programme evidence is supplied.

Known limitations requiring follow-up

  • Long-horizon warning: the sourced 12-month Malawi household term makes the five-year reference run viable, but the current 20-year stress scenario eventually becomes insolvent because lower interest earned per loan does not cover indefinite operating costs. This result is disclosed rather than tuned away.
  • Constraint label question: the model specification still asks whether the headline “dominant constraint” should be derived directly from the production minimum. The underlying production arithmetic is unaffected.
  • Calibration: financing, operating-cost, loss, capacity, contingency, and subsidy assumptions remain illustrative until replaced with programme evidence.

Earlier stages

  • 0.5.0 / S5: split the application into pure model, UI, data, and controller modules with no behavior change.
  • 0.4.0 / S4: replaced unsafe monotonic solver assumptions with grid-then-bisect searches and explicit failure results.
  • 0.3.0 / S3: corrected reserves, enterprise capital, terminal wind-up, impact service life, and model mathematics.
  • 0.2.0 / S0–S2: added the safety net, fixed silent input and unit errors, separated integrity from viability, and stopped the controller rewriting user inputs.
